# 模组适用端与客户端包

Thunderstore 的标准包清单包含名称、版本和依赖等信息，没有统一的客户端/服务器适用端字段。因此面板不会把未声明的模组自动当作“两端使用”，也不会采信任意包中的非标准 `side` 字段。

面板内置确认 Nebula、Nebula API 和 BepInEx 为两端组件，Dyson Control Bridge 仅用于服务器。其他模组在“已安装”中显示“适用端待确认”。管理员应查看当前版本作者的说明，再选择“两端使用”“仅服务器”或“仅客户端”。确认记录保存在私有数据目录，按模组和具体版本绑定；更新版本后需要重新确认。

这项设置控制客户端包内容，不移动、不停用服务器上的文件。生成 `.r2z` 时会排除已停用和仅服务器模组，并要求所有已启用模组的适用端已确认、Thunderstore 包身份已识别、安装版本可精确表达。客户端仍须实际导入并入服验证兼容性。

“客户端 → 创建前检查”会一次列出待确认的适用端、缺少作者名或包名的安装项、无法精确导出的版本，以及本地能核对的模组。修正后刷新即可查看将纳入的精确版本。点“创建客户端包”后，任务会重新读取安装记录。检查期间仍可下载已有配置包。

在“客户端”页选择具体的文件，可以看到包内的连接地址、模组包名和精确版本，以及它们与当前配置的差异。新包使用独立文件名，面板会在查看详情或下载时核对文件与生成记录。展开“文件 SHA-256”即可与玩家手上的文件比对。缺少地址和版本记录的旧包显示“未知”，仍可下载。地址、模组版本或适用端变动后，可创建新包再分发。

玩家在 r2modman 的配置选择页点击 **Import / Update → From file**，选择下载的 `.r2z`。在 **Packages to be installed** 页核对每个模组及版本，点击 **Import → Import new profile**，确认配置名后点击 **Create**。如果有模组无法识别，先核对版本和下载来源。等列出的模组下载完成，再从该配置启动与服务器版本一致的游戏。

选中与当前配置一致的包，点击“下载入服说明”，即可把文本与对应的 `.r2z` 一起交给玩家。说明列出游戏地址、文件大小、SHA-256、锁定的模组版本以及校验和导入步骤。生成说明时面板再次核对包和当前配置。你也可以在“文件 SHA-256 与本地核对”中选择本机副本，浏览器直接比较字节数和 SHA-256。仅通过普通内网 HTTP 访问时，可按页面给出的 PowerShell 命令核对。

首次使用全新的游戏用户数据目录时，先启动一次纯净游戏、选择语言并正常退出，让游戏写入初始选项，再启动模组配置。实测 CommonAPI 1.6.7 与 UXAssist 1.5.8 的组合在选项尚未初始化时可能卡在语言选择，并记录数组长度或快捷键索引错误；完成纯净游戏初始化后可正常进入模组主菜单。此步骤不需要删除已有存档或重置其他配置。

依据：[Thunderstore 包格式](https://wiki.thunderstore.io/mods/creating-a-package)、[Nebula 安装说明](https://github.com/NebulaModTeam/nebula/wiki/Installation)。
