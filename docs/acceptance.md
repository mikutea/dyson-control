# 项目发布验证与部署检查

Dyson Control 面向用户自行搭建服务器。项目发布验证关注公开安装包能否让新用户安装和使用；部署后的网络检查针对用户自己的主机与联机地址。维护者自用服务器的域名、IP 或公网连通状态不构成项目发布条件。

本地夹具、演示页面和编译结果用于验证实现。真实游戏验证使用同一份已校验发布包，记录实际结果；未执行的项目保持“未验证”。存档、玩家记录、主机路径、网络配置和日志存于私有目录，不提交到公开仓库。首版范围以 [GOAL.md](../GOAL.md#首版交付口径) 为准。

## 项目发布验证

- 公开源码、完整安装包、版本说明和文档一致；下载入口与 SHA-256 校验值可用，完整包包含与支持的游戏和模组版本匹配的 Bridge。
- 按公开文档使用独立配置和空游戏目录完成首装、启动、保存、备份恢复，并用匹配客户端连接。所需账号、Windows/Steam 会话和依赖写清楚，不依赖维护者的私有目录或配置。
- 接入已有游戏、升级、失败回退和卸载遵守原有数据边界；卸载保留用户的游戏、配置和存档。
- 仓库、图片和发布包不包含维护者服务器的访问域名、IP、凭据或用户资料。示例只使用本机地址、保留的示例地址及通用目录。

## 用户部署前

1. 获取与所用游戏和模组版本匹配的完整发布包，核对版本说明和 ZIP 的 SHA-256。
2. 核对自己的 Windows 用户、Steam 会话、游戏和数据目录。接入已有服时确认当前游戏进程与启动任务，避免选错实例。
3. 接入或升级已有服务器时，由游戏完成一次保存，将 `.dsv`、同名 `.server` 和已有 `.moddsv` 作为一个整体备份，复读文件大小与 SHA-256。保留原 Bridge、配置、任务 XML、面板版本和安装状态。
4. 接入已有游戏时，使用 `configure-game.ps1 -PrepareOnly` 生成接入计划，核对实际变更，再在计划停服窗口应用。空目录首装会由面板完成相应配置，见[安装与授权](server-setup.md)。

## 功能验收

下表用于检查实际部署与后续完整功能；首版未承诺的无人值守和容量能力可以明确列为限制，不要求每位用户重复完整测试。

| 流程 | 实际通过证据 |
| --- | --- |
| 启动、保存、停止、重启 | 受管 PID 与新鲜签名 Bridge 状态一致；保存回执与完整文件组一致；停止后原 PID 确实退出；重启得到新的就绪进程 |
| 备份与恢复 | 下载备份可复读；恢复前副本存在；恢复后整组散列正确，游戏能加载目标存档 |
| 模组与配置 | 安装、启用、停用、移除和恢复实际改变对应包；依赖冲突在停服前报告；配置预览、历史恢复与密钥保留正确 |
| 更新与版本锁 | 游戏、Nebula、BepInEx 和普通模组显示实际版本；依赖与锁定检查生效；更新后可启动，失败测试能恢复原内容 |
| 更新中断恢复 | 在隔离目录模拟中断；下次操作恢复已验证的原状态；未知文件变更不被覆盖；记录与实际版本一致 |
| 玩家 | 实际加入、离开对应签名事件；踢出仅针对所选会话连接，并等待游戏正常清理；断开后可以重新加入 |
| 客户端包 | 新建隔离的 r2modman 配置，实际导入 `.r2z`、下载锁定版本，并用该配置加入服务器；不能以 ZIP 可解析代替实际导入 |
| 日志和监控 | 页面关闭后仍采样、备份；日志过滤与下载可用；CPU、内存、磁盘、UPS、TPS 和网络的实际采集口径明确，缺失值不当作零；游戏就绪且队列空闲时，UPS 为正但 TPS 连续一分钟为零须提示世界未推进，恢复推进后解除告警 |
| 故障恢复 | 游戏意外退出触发有次数上限的恢复；手动停止不会自动启动；变更失败会暂停自动恢复 |
| 重启后的恢复 | 面板任务随 Windows 启动；游戏恢复依赖游戏用户与桌面 Steam 会话。只有实际验证无需人工登录即可恢复后，才能承诺完全无人值守 |

名单和角色权限不属于当前 Nebula 版本提供的接口。不要用存档身份、全局密码或内部远程命令登录集合冒充这些能力，详见 [Bridge](bridge.md)。

## 网络、性能与观察

部署者分别检查自己的管理入口和游戏入口。远程管理使用 HTTPS，并检查证书与未登录访问；在局域网开服时，先用局域网客户端加入；计划向互联网玩家开放时，再用外部网络客户端加入自己的 Nebula 地址。网页、TCP 探测和端口监听不能代替实际入服。具体配置见[连接自己的服务器](networking.md)。

性能记录至少注明存档、硬件、游戏与模组版本、玩家数量、目标 UPS、实测 UPS/TPS、CPU、内存和观察时段。先获得固定存档的空载基线，再增加真实玩家与实际工厂负载，记录下降点和恢复情况。以 60 UPS 为目标，不能把启动参数设为 60 当作达到 60 的证据。

UPS 描述引擎更新频率，TPS 根据签名的游戏 tick 增量计算。UPS 为正而 TPS 为零时，世界可能没有推进，不能据此认定持续运转通过。持续零 TPS 告警只报告状态，不触发进程重启；暂停或不可用的空遥测、执行中的游戏操作、进程变化和读取失败会中断其连续观察窗口。

持续观察期间记录异常退出、恢复次数、自动备份、磁盘余量和资源增长。最终报告应分别列出已验证流程、未验证流程、实测容量与已知限制，并保留可执行回退步骤。
