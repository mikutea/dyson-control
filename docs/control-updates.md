# 面板自身更新

“版本”页面显示正在运行的面板版本，并可从配置的 GitHub 仓库检查正式 Release。更新源尚未配置、尚无正式发布或下载失败时，界面会明确显示原因，不会把未知状态当作“已是最新”。

在私有 `control.config.json` 顶层添加所信任的公开发布仓库：

```json
"controlUpdates": {
  "repository": "your-org/dyson-control"
}
```

把 `your-org/dyson-control` 替换为实际发布此面板的仓库。只接受 `owner/repository` 格式；此设置决定可安装代码的来源，应只由主机管理员修改。无需保存 GitHub 令牌。

## 下载与安装

1. 在“版本”页检查更新，然后选择“下载并校验更新”。准备过程下载正式 Release 中的 `*-windows-panel-only.zip` 及同名 `.sha256`，核对仓库、版本、大小、SHA-256、归档路径和发布清单。
2. 准备完成后选择“安装面板更新”并确认。只有 Windows 安装程序建立的受管 SYSTEM 面板实例才能安装；源码运行、演示模式及无法证明安装归属的实例只允许检查与准备。
3. 独立 SYSTEM 更新任务等待当前游戏操作及上传结束，再停止旧面板并启动候选版本。更新不会替换游戏、存档、模组或 Bridge。面板短暂离线期间，页面会保留更新回执并等待重连。
4. 只有新的面板进程返回匹配版本、安装路径及可接受请求的健康证据时，才显示安装成功。候选启动失败且旧版本重新通过健康检查时，才显示“已恢复原版本”。无法证实恢复时记录失败，不能把尝试回退当作成功。

面板重启后登录会话失效，需要重新登录。当前浏览器标签页保留一个只读更新回执，可在登录前查询这一次更新的结果；它不能提交操作或读取其他更新。回执不会出现在 URL 中，服务器只保存其哈希，终态后保留 24 小时。关闭标签页后可登录“版本”页查看持久历史。

准备好的候选可在页面取消。24 小时未安装的候选自动失效并清理下载文件，历史记录保留。服务重启后未完成的下载会记录中断，不会自动重放安装。

## Bridge 与手动维护

面板自更新只消费明确标记的 `panel-only` 包。Bridge 在游戏进程中加载，更新 Bridge 必须按照 [游戏接入](game-configuration.md) 在停服窗口实施，使用完整发布包内经过校验的候选。

面板升级会保留正在运行的游戏任务。任务仍引用同一安装目录的旧版本时，只有 `start-game.ps1` 和 `path-policy.ps1` 与当前版本逐字节一致，才继续识别为受管启动。若这两个文件发生变化，请按游戏接入文档在停服窗口重新配置；面板不会在游戏运行中改写其启动任务。

首次安装、离线升级和手动回退使用 [Windows 安装说明](installation.md) 中的脚本。不要把“准备完成”当作安装完成，也不要以计划任务已注册代替运行健康检查。
