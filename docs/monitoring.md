# 后台监控与玩家历史

面板进程启动后，监控不依赖浏览器连接。运行状态每 15 秒采样一次，玩家事件每 5 秒读取一次。运行记录存于私有数据目录的 `runtime.sqlite`，玩家历史存于 `players.sqlite`；请勿将这些文件放入公开仓库或发布包。

## 自动备份与故障恢复

默认每 60 分钟自动备份。管理员可以在“设置 → 自动备份与恢复”调整间隔；设为 0 关闭。到期后，监控等待游戏运行、Bridge 就绪且任务队列空闲，再提交普通备份任务。每次先由游戏确认保存，再打包完整存档组。失败会进入活动记录和告警，下一周期再尝试；维护期间不提交自动操作。

自动轮换按“设置 → 保留备份”留下最近的自动副本，默认 20 份。希望长期保留定时备份或变更前的保护副本时，在“存档 → 备份”找到对应的创建时间，点“保留此备份”。该副本及其下载缓存单独保留，不占最近 20 份的名额。标记保存在面板私有数据目录，重启后继续生效。点“取消保留”只撤销标记，后续轮换才可能清理超出数量的副本。

轮换会跳过手动备份、导入备份、状态不明的保留标记，以及含陌生文件的目录。刚完成的保护副本也会保留到本轮结束，即使时钟回拨也能在列表中找到。本次备份失败时保留已有副本。

自动启动默认关闭。开启时只有最近实际运行的游戏，或管理员随后手动启动的游戏，才会被列入恢复范围。手动停止后不会重新启动。观测到明确停止持续 30 秒、面板启动已超过 60 秒后才尝试恢复；读取失败或状态未知不会触发启动。最多在 30 分钟内尝试 3 次，并逐步延长重试间隔。失败的手动游戏变更会暂停恢复，管理员检查活动记录并成功手动启动后才解除。

Windows 主机重启后，面板可能比桌面 Steam 先就绪。到达恢复时间时，面板核对受管游戏任务，并查找该任务用户在非零 Windows 会话中运行的桌面 Steam。缺少对应 Steam、Steam 属于其他用户、同一用户在多个会话中运行 Steam，或权限不足无法确认时，“后台运行”会显示等待原因，约一分钟后复查。等待期间保留剩余启动次数。条件满足后，通过原任务队列尝试启动；启动脚本会用自身实际所在的 Windows 会话和用户身份再次核对 Steam。

游戏与模组变更、手动备份和自动操作共用一个持久化任务队列。所有操作记录都可在“活动”中查看。

后台设置保存前可预览更改；设置历史保留最近 100 个版本，包含首次修改前的设置。恢复历史版本会立即调整后续备份计划和告警阈值，同时保留当前版本，便于撤回。开启崩溃恢复仍遵守上述运行状态条件，不会仅因恢复了一条设置就启动原本停止的游戏。

## 导入现有存档

在“存档 → 导入备份”选择 ZIP，单次上传上限为 8 GiB。Dyson Control 导出的备份按原 `manifest.json` 核对大小与 SHA-256。如果手上只有存档文件，把同一个世界的 `.dsv`、`.server` 和已有的 `.moddsv` 一起压缩。三者共用完全相同的档名，放在 ZIP 根目录或同一个一级文件夹中。例如 `迁移/星团.dsv` 和 `迁移/星团.server` 可以组成一份备份。

普通存档 ZIP 只收录这一个世界的非空成员。中文文件名需由 ZIP 标明 UTF-8，或附带可校验的 Unicode 路径记录。面板在解压时检查每个文件的 CRC 和字节数，再为备份清单记录 SHA-256。相同名字的不同版本可以并存，重新选择完全相同的 ZIP 时会提示对应备份 ID 已存在。

导入完成后可在备份列表中校验，或预览恢复时将写入哪些文件。确认恢复后才会修改游戏存档。Windows 提供包含清单的备份下载，演示模式提供已核验的上传原 ZIP。

## 校验备份

在“存档 → 备份”点击“校验”，逐个检查清单中的 `.dsv`、同名 `.server` 和已有 `.moddsv` 的文件类型、大小与 SHA-256。文件缺失、内容被修改、出现清单未记录的存档成员或校验期间发生变化时，任务会失败并说明对应文件。校验只读取备份，既不恢复存档，也不启动、停止或保存游戏。

结果和校验时间保存在“活动”的操作记录中，仅表示该次检查时文件与备份清单一致，不代替真实游戏加载验证，也不能保证此后的存储状态。恢复和下载仍会重新校验文件。校验与其他任务串行执行；关闭服务或超时会中止读取，不自动重试。

## 恢复备份

在“存档 → 备份”点击“恢复”，可以先查看同名存档哪些文件将新建、替换或移除，运行中的世界是否需要停服，以及下次启动将选用哪个存档。取消预览会返回列表。确认后服务重新检查文件范围和运行状态，校验备份成员，保存可恢复的保护副本，再执行替换。发现目标多出文件、游戏进程变化或备份内容损坏时，先处理提示，再重新预览。

## 加载已有存档

在“存档 → 游戏存档”选择“加载”，确认后从该存档启动服务器。运行中的世界会先由 Bridge 确认保存并创建完整保护备份，再优雅停止；所选存档也会在启动前保留保护副本。`.dsv`、同名 `.server` 和已有 `.moddsv` 始终整组处理，不替换存档文件。需要使用 Dyson Control 管理的启动任务。

加载成功会确认新进程使用指定存档的启动参数，且该进程的签名 Bridge 已就绪，后续启动继续选择这一存档。若启动失败，已写入的存档选择和保护备份会保留，活动记录说明当前步骤；自动恢复暂停。检查服务器状态后可重试启动，或从备份恢复。中断操作不会自动重放。

## 指标与告警

CPU 和内存来自受管游戏进程，磁盘表示存档卷剩余空间；UPS、TPS 来自 Bridge 的实际游戏采样。不可用的数据返回空值，不用目标 UPS 代替实际值。运行采样保留 7 天，长时间范围按时间分组展示。

CPU 使用实际读取进程计数器的时间计算，并按逻辑处理器数量归一化。页面与后台监控读取同一个短期缓存样本时，保留该样本已计算的 CPU 和网络速率；重复读取不会生成一个新的零值样本。游戏进程替换后，CPU 从新的基线重新计算。

展开“后台运行 → 查看运行历史”，可选择最近一小时、一天或一周，切换指标并翻看明细。趋势图以服务器时间为横轴，每个时间段展示最后一个采样点，最多 720 点。缺失的时间段或读数留白，进程和运行状态变化时断开曲线。点击“原始 CSV”可下载所选范围内逐条记录的采样，按 UTC 时间升序排列，保留零值并将缺失项留空。长时间范围的趋势图可能省略短暂波动，排查短时停顿可使用原始记录。

网络显示主机处于 Up 状态的物理网卡收发总速率，通过 `Get-NetAdapter -Physical` 和 `Get-NetAdapterStatistics` 的累计字节差计算；不表示游戏进程专属流量。首次采样、网卡集合变化、计数器重置、没有符合条件的网卡或读取失败时显示不可用。虚拟网卡与隧道不参与合计；若虚拟机只暴露虚拟接口，此项可能没有数据。采集口径依据 [Get-NetAdapter](https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapter) 与 [Get-NetAdapterStatistics](https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapterstatistics)。

默认磁盘低于 5 GiB，或实际 UPS 连续一分钟低于 30 时告警。后台还会显示 Bridge 未就绪、读取失败、备份失败、游戏意外停止和恢复暂停。告警目前在管理页面呈现，没有外部邮件或手机推送。

## 查找管理操作

在“活动 → 管理操作”中可以按操作类型和状态筛选。例如选择“创建备份”和“未完成”，就能找到失败的备份，并展开步骤查看原因。任务被服务重启中断时，状态为“已中断”。

筛选会查找数据库中所有保留的操作，按创建时间从新到旧排列，每页最多 25 条。翻到下一页可继续查看更早的操作，切换筛选条件会回到第一页。查看历史不会重试任务。

提交后连接中断时，同一浏览器标签页会保留操作名称和随机请求编号。恢复连接后点击“核对回执”，可以找回已入队的任务，刷新页面后也能核对。若仍查不到任务，可回到原入口再次提交；同一编号只会执行一次。浏览器保存的回执信息不含存档名称或配置内容。

## 查看与导出日志

打开“活动 → 服务器消息”后，页面每 5 秒读取一次最近日志。可以暂停自动刷新以阅读某段消息，也可以手动刷新；离开服务器消息视图后停止轮询。暂停期间，其他管理任务完成不会替换当前日志快照。

按级别和关键词筛选消息，“下载筛选快照”下载当前显示的结果。快照的顺序、条目与筛选结果一致，不包含未读到的历史日志。尚未生成日志时列表为空；日志路径不是普通文件或服务无法读取它时，活动页提示读取失败，保留上次成功读取的消息。修正路径或权限后可刷新恢复。

日志列表只将行首完整日期时间识别为事件时间，支持带方括号的时间及 UTC/时区偏移；没有时区的完整时间按服务器本地时区解释。未记录完整时间、只有时分秒、日期无效或日期只出现在正文中的行，显示“时间未记录”，不使用文件修改时间补齐。列表按文件中的先后顺序倒序显示。

每次最多读取日志末尾 512 KiB，并显示最近 500 条非空行，每条最多显示 2,000 字符；截断窗口可能不完整的首行会被丢弃。追加新行不会改变已有行的 ID 或事件时间。需要原始文件内容时，使用“服务器”页已有的日志下载入口，最多下载原文件末尾 16 MiB；该下载与筛选快照分开，不补写时间。

## 玩家进出记录

在线列表只使用新鲜、签名有效且绑定当前游戏进程的 Bridge 状态。每次连接使用游戏会话内独立编号，同一玩家再次连接会产生新的连接编号。

历史中的“加入”和“离开”来自 Nebula 对应回调。“首次观测在线”用于 Bridge 开始观察时已存在的连接，不表示真实加入时间。Bridge 保留最近 256 条事件；面板按会话和事件序号去重。若面板离线过久导致窗口前部已被覆盖，会显示缺失事件数量。完全发生在面板未读取到的游戏会话中的事件无法恢复，因此历史不保证覆盖全部运行时间。

停服后仍可读取最后的签名事件窗口。在线列表为空或读取失败不会自动生成离开事件。历史保存显示名称、事件类型、时间和临时连接编号，不保存 IP、平台账号或认证材料。保留最近 30 天，最多 10,000 条，超过范围自动清理。数据库备份的保存期限由部署者管理。

## 验证边界

本地测试覆盖采样、自动任务去重、恢复次数限制、维护暂停、玩家事件签名、去重、重启重读、窗口缺失和历史保留。真实游戏持续运行、实际崩溃恢复、存档恢复和外部客户端加入仍须按部署验收单单独验证。
