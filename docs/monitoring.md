# 后台监控与玩家历史

面板进程启动后，监控不依赖浏览器连接。运行状态每 15 秒采样一次，玩家事件每 5 秒读取一次。运行记录存于私有数据目录的 `runtime.sqlite`，玩家历史存于 `players.sqlite`；请勿将这些文件放入公开仓库或发布包。

## 自动备份与故障恢复

默认每 60 分钟自动备份。管理员可以在“设置 → 自动备份与恢复”调整间隔；设为 0 关闭。到期后，监控等待游戏运行、Bridge 就绪且任务队列空闲，再提交普通备份任务。每次先由游戏确认保存，再打包完整存档组。失败会进入活动记录和告警，下一周期再尝试；维护期间不提交自动操作。

自动备份按“设置 → 保留备份”保留最近的副本，默认 20 份。每次定时备份完整复制并通过校验后，清理超出保留数量的旧自动备份整组及其下载 ZIP 缓存。本次新副本始终受保护；若时钟回拨导致它排序较早，会额外保留该副本，因此数量可能超过设置值。手动备份、导入备份和非托管目录不参与清理；本次备份失败、未生成完整新副本时，不触发此次保留清理。

自动启动默认关闭。开启时只有最近实际运行的游戏，或管理员随后手动启动的游戏，才会被列入恢复范围。手动停止后不会重新启动。观测到明确停止持续 30 秒、面板启动已超过 60 秒后才尝试恢复；读取失败或状态未知不会触发启动。最多在 30 分钟内尝试 3 次，并逐步延长重试间隔。失败的手动游戏变更会暂停恢复，管理员检查活动记录并成功手动启动后才解除。

游戏与模组变更、手动备份和自动操作共用一个持久化任务队列。所有操作记录都可在“活动”中查看。

后台设置保存前可预览更改；设置历史保留最近 100 个版本，包含首次修改前的设置。恢复历史版本会立即调整后续备份计划和告警阈值，同时保留当前版本，便于撤回。开启崩溃恢复仍遵守上述运行状态条件，不会仅因恢复了一条设置就启动原本停止的游戏。

## 加载已有存档

在“存档 → 游戏存档”选择“加载”，确认后从该存档启动服务器。运行中的世界会先由 Bridge 确认保存并创建完整保护备份，再优雅停止；所选存档也会在启动前保留保护副本。`.dsv`、同名 `.server` 和已有 `.moddsv` 始终整组处理，不替换存档文件。需要使用 Dyson Control 管理的启动任务。

加载成功会确认新进程使用指定存档的启动参数，且该进程的签名 Bridge 已就绪，后续启动继续选择这一存档。若启动失败，已写入的存档选择和保护备份会保留，活动记录说明当前步骤；自动恢复暂停。检查服务器状态后可重试启动，或从备份恢复。中断操作不会自动重放。

## 指标与告警

CPU 和内存来自受管游戏进程，磁盘表示存档卷剩余空间；UPS、TPS 来自 Bridge 的实际游戏采样。不可用的数据返回空值，不用目标 UPS 代替实际值。运行采样保留 7 天，长时间范围按时间分组展示。

CPU 使用实际读取进程计数器的时间计算，并按逻辑处理器数量归一化。页面与后台监控读取同一个短期缓存样本时，保留该样本已计算的 CPU 和网络速率；重复读取不会生成一个新的零值样本。游戏进程替换后，CPU 从新的基线重新计算。

网络显示主机处于 Up 状态的物理网卡收发总速率，通过 `Get-NetAdapter -Physical` 和 `Get-NetAdapterStatistics` 的累计字节差计算；不表示游戏进程专属流量。首次采样、网卡集合变化、计数器重置、没有符合条件的网卡或读取失败时显示不可用。虚拟网卡与隧道不参与合计；若虚拟机只暴露虚拟接口，此项可能没有数据。采集口径依据 [Get-NetAdapter](https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapter) 与 [Get-NetAdapterStatistics](https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapterstatistics)。

默认磁盘低于 5 GiB，或实际 UPS 连续一分钟低于 30 时告警。后台还会显示 Bridge 未就绪、读取失败、备份失败、游戏意外停止和恢复暂停。告警目前在管理页面呈现，没有外部邮件或手机推送。

## 日志时间

日志列表只将行首完整日期时间识别为事件时间，支持带方括号的时间及 UTC/时区偏移；没有时区的完整时间按服务器本地时区解释。未记录完整时间、只有时分秒、日期无效或日期只出现在正文中的行，显示“时间未记录”，不使用文件修改时间补齐。列表按文件中的先后顺序倒序显示。

每次最多读取日志末尾 512 KiB，并显示最近 500 条非空行；截断窗口可能不完整的首行会被丢弃。追加新行不会改变已有行的 ID 或事件时间。实际服务器的日志下载保留原始文件内容，不补写时间。

## 玩家进出记录

在线列表只使用新鲜、签名有效且绑定当前游戏进程的 Bridge 状态。每次连接使用游戏会话内独立编号，同一玩家再次连接会产生新的连接编号。

历史中的“加入”和“离开”来自 Nebula 对应回调。“首次观测在线”用于 Bridge 开始观察时已存在的连接，不表示真实加入时间。Bridge 保留最近 256 条事件；面板按会话和事件序号去重。若面板离线过久导致窗口前部已被覆盖，会显示缺失事件数量。完全发生在面板未读取到的游戏会话中的事件无法恢复，因此历史不保证覆盖全部运行时间。

停服后仍可读取最后的签名事件窗口。在线列表为空或读取失败不会自动生成离开事件。历史保存显示名称、事件类型、时间和临时连接编号，不保存 IP、平台账号或认证材料。保留最近 30 天，最多 10,000 条，超过范围自动清理。数据库备份的保存期限由部署者管理。

## 验证边界

本地测试覆盖采样、自动任务去重、恢复次数限制、维护暂停、玩家事件签名、去重、重启重读、窗口缺失和历史保留。真实游戏持续运行、实际崩溃恢复、存档恢复和外部客户端加入仍须按部署验收单单独验证。
